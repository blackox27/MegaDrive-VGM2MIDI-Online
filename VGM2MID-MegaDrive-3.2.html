    VGM2MID Mega Drive Studio 3.2

    Abra, escolha os timbres e toque.

    1. Abra o HTML em um navegador moderno. Não requer instalação, servidor ou conexão com a internet.
    2. Use o seletor no cabeçalho para escolher Português (BR) ou English. A preferência é lembrada quando o armazenamento do navegador está disponível. Trocar o idioma preserva a fila, os ajustes, a posição e a soundfont carregada.
    3. Use Adicionar músicas ou o quadro de músicas para VGM, VGZ, VGM comprimido em GZIP ou GYM. Use Carregar SF2 ou o quadro Soundfont separado para uma .sf2. O pacote inclui a fonte enviada na pasta assets/soundfonts.
    4. Experimente as demos PSG, DAC e SegaPCM. Escolha instrumento, preset SF2, volume e transposição por pista. Os botões acima da tabela ativam ou desativam todas as pistas.
    5. Reproduza, pause, pare ou busque uma posição. A tecla Espaço reproduz/pausa quando o foco está fora dos campos. Os osciloscópios mostram o áudio real da prévia, com ganho visual automático e indicador de nível RMS. Desativar Animações reduz os destaques de notas; o monitoramento de ondas continua.
    6. Revise trechos PCM/DAC: ouça, baixe o WAV reconstruído, ignore ou atribua uma nota/percussão manual. O monitor funciona também quando o trecho está excluído do MIDI.
    7. Baixe MIDI ou o lote ZIP com diagnósticos. O MIDI inclui notas, controles e bancos/programas escolhidos, mas não incorpora a soundfont ou samples PCM. Para usar esses timbres em outro aplicativo, carregue a mesma SF2.

    Entradas e chips compatíveis

    Cabeçalhos VGM 1.00–1.72, VGZ/GZIP, metadados GD3 e loops por comandos são suportados. GYM aceita PSG/YM2612 a 50/60 Hz; GYMX com compressão interna precisa ser descompactado e seus loops de cabeçalho não são expandidos.

    A transcrição por registros inclui SN76489, AY8910, YM2612, YM2151, YM2413, YM2203, YM2608, YM2610, YM3812, YM3526, Y8950, YMF262, Game Boy, NES APU, HuC6280, SAA1099 e SCC/K051649. Dados de ROM/canais SegaPCM e streams DAC YM2612 compatíveis podem ser reconstruídos para transcrição PCM aproximada. Reconhecer um comando não significa emular todos os recursos do chip.

    PCM e precisão musical

    VGM contém comandos de chips, e não a partitura original. A análise PCM estima notas monofônicas ou percussão a partir do áudio reconstruído. Acordes, instrumentos misturados, fala, ruído, fundamentais fracas e ataques sem silêncio podem gerar erros de notas, oitavas e limites de trechos. Periodicidade é uma medida de análise, não uma probabilidade calibrada de acerto. Revise os resultados. A saída WAV recuperada é mono a 22.050 Hz.

    Soundfonts

    O sampler aceita samples SF2 PCM16, zonas por tecla/velocidade, bancos/programas, afinação, pan, loops e envelopes de volume. Alguns presets têm extensão de teclado limitada. Filtros, LFOs, moduladores, classes exclusivas e efeitos avançados não são implementados integralmente. SF3/Ogg não é suportado; fontes de 24 bits usam sua componente de 16 bits. Nomes originais dos samples e presets são preservados em ambos os idiomas.

    Opções e limites

    BPM altera a grade MIDI preservando o tempo em segundos; não é um controle de velocidade da prévia. Transposição é medida em semitons. Passagens de loop afetam a reconversão. Pitch bend preserva alterações explícitas de afinação; notas discretas podem fragmentar vibratos. Mais de 15 pistas melódicas ou várias pistas de percussão usam portas MIDI adicionais, que precisam ser respeitadas pelo editor de destino.

    Limites: 20 músicas e 256 MB de entrada por lote, 64 MB por música, 128 MB descompactados, 30 minutos e 8 passagens. PCM: 16 milhões de capturas, 4 milhões de passos de stream, 64 MB contabilizados de áudio recuperado e 2.048 trechos. ROM SegaPCM: 64 MB por chip. SF2: 256 MB de entrada e 64 MB de cache de AudioBuffers. Prévia: até 256 vozes de sample/oscilador e 16 camadas SF2 por nota. Monitores exibem 12 pistas por página e PCM exibe 20 trechos por página.

    RF5C68/164, PWM, OPL4, QSound e outros chips/ADPCM não suportados continuam fora da transcrição. MP3, WAV, MIDI, NSF, SPC e ROMs avulsas não podem ser importados como músicas. Silêncio e arquivos apenas com chips não suportados não geram um MIDI vazio.

Reconstrua com python3 scripts/build.py. O uso do aplicativo não requer dependências.

    VGM2MID Mega Drive Studio 3.2

    Open, choose sounds and play.

    1. Open the HTML file in a modern browser. No installation, server or internet connection is required.
    2. Use the language selector in the header to choose Português (BR) or English. The choice is remembered when browser storage is available. Switching language preserves the queue, track settings, playback position and loaded soundfont.
    3. Use Add music or the music drop area for VGM, VGZ, GZIP-compressed VGM or GYM files. Use Load SF2 or the separate Soundfont area for one .sf2 file. The complete package includes the supplied Mega 16-Bit FM soundfont in assets/soundfonts.
    4. Try the PSG, DAC and SegaPCM demos. Select an instrument, SF2 preset, volume and transposition per track. Enable all or disable all tracks with the buttons above the table.
    5. Play, pause, stop or seek. Space plays/pauses when focus is outside input controls. Oscilloscopes show the actual preview audio with automatic visual gain and an RMS level indicator. Disable animations to reduce note highlights; waveform monitoring remains active.
    6. Review recovered PCM/DAC regions. Listen to a region, download its reconstructed WAV, ignore it or manually assign a MIDI note/percussion key. The region monitor also works when a region is excluded from MIDI.
    7. Download MIDI or the batch ZIP with diagnostics. MIDI includes notes, controls and selected banks/programs, but does not embed the soundfont or PCM samples. Load the same SF2 in another synthesizer to use those sounds.

    Supported input and chips

    VGM headers 1.00–1.72, VGZ/GZIP, GD3 metadata and command loops are supported. GYM supports PSG/YM2612 at a selected 50/60 Hz; internally compressed GYMX must first be decompressed, and GYMX header loops are not expanded.

    Register-based transcription includes SN76489, AY8910, YM2612, YM2151, YM2413, YM2203, YM2608, YM2610, YM3812, YM3526, Y8950, YMF262, Game Boy, NES APU, HuC6280, SAA1099 and SCC/K051649. SegaPCM ROM/channel data and supported YM2612 DAC streams can be reconstructed for approximate PCM transcription. Recognizing a command does not imply emulating every feature of its chip.

    PCM and musical accuracy

    VGM contains chip commands rather than the original score. PCM analysis estimates monophonic notes or percussion from reconstructed audio. Chords, mixed instruments, speech, noise, weak fundamentals and attacks without silence can produce incorrect notes, octaves or region boundaries. Periodicity is an analysis measure, not a calibrated probability of correctness. Review results manually. Recovered WAV output is mono at 22,050 Hz.

    Soundfonts

    The preview sampler supports PCM16 SF2 samples, key/velocity zones, banks/programs, tuning, pan, loops and volume envelopes. Some presets have a limited keyboard range. Advanced filters, LFOs, modulators, exclusive classes and effects are not fully implemented. SF3/Ogg is unsupported; 24-bit fonts use their 16-bit component. Original SF2 sample and preset names are preserved in either interface language.

    Options and limits

    BPM changes the MIDI grid while preserving timing in seconds; it is not a playback speed control. Transposition is in semitones. Loop passes affect reconversion. Pitch bend preserves explicit tuning changes; discrete notes may fragment vibrato. More than 15 melodic tracks or multiple percussion tracks use additional MIDI ports that the receiving editor must support.

    Limits: 20 songs and 256 MB of input per batch, 64 MB per song, 128 MB decompressed, 30 minutes and 8 loop passes. PCM limits: 16 million captures, 4 million stream steps, 64 MB counted recovered audio, 2,048 regions. SegaPCM ROM: 64 MB per chip. SF2: 256 MB input and 64 MB AudioBuffer cache. Preview: up to 256 sample/oscillator voices and 16 SF2 layers per note. Monitors display 12 tracks per page; PCM displays 20 regions per page.

    RF5C68/164, PWM, OPL4, QSound and other unsupported chips/ADPCM remain outside transcription. MP3, WAV, MIDI, NSF, SPC and standalone ROM files cannot be imported as songs. Silence and unsupported-only files do not generate an empty MIDI.

    Source code

    src/core contains conversion; src/audio contains playback, SF2 and waveform processing; src/ui contains rendering; src/io contains import/export; src/i18n contains both catalogs and language handling; src/styles contains CSS; src/workers contains the conversion protocol. docs contains bilingual help and the review, scripts contains build/package tools, tests contains verification and fixtures, and assets/soundfonts contains the supplied SF2. Build with python3 scripts/build.py. Runtime requires no dependencies.

    Revisão 3.2 · 15 de outubro de 2026

    Revisão de código e internacionalização

    A revisão mantém a conversão VGM/GYM e a reprodução SF2 da edição 3.1, acrescenta seleção PT-BR/EN e organiza os fontes por responsabilidade. O HTML final continua independente e abre por arquivo local. A soundfont fornecida permanece sem alterações.

    Idiomas

    Os catálogos locais traduzem legendas, opções GM, controles, mensagens de conversão/erro, atributos de acessibilidade e diagnósticos. Ajuda e análise têm documentos próprios em português e inglês. O atributo lang do HTML acompanha a seleção. A preferência usa armazenamento local com tratamento de falhas; se o navegador negar acesso, a troca funciona durante a sessão. Não há serviço de tradução nem requisições de rede. Nomes de arquivos, metadados e nomes próprios da SF2 são preservados.

    Correções

    O quadro de músicas deixa de sugerir SF2; arquivos de tipos diferentes permanecem separados. A troca de página PCM encerra sua audição para evitar monitor removido enquanto o áudio continua. O monitor mantém notas sobrepostas separadamente, evitando apagar teclas de uma nota longa quando outra curta termina. A legenda do instrumento reflete o motor de áudio escolhido. A reprodução não inicia durante conversão ou carregamento de fonte. Diagnósticos identificam a prévia realmente selecionada.

    O sampler limpa vozes já iniciadas caso uma camada posterior falhe e respeita as vagas restantes do limite de reprodução. A interface oferece ativar/desativar todas as pistas e atalho de Espaço fora dos campos. A troca de idioma não recria os controles nem altera ajustes, fila ou reprodução.

    Otimização

    Buffers de leitura e do traço dos osciloscópios são reutilizados entre quadros. A renderização continua em até aproximadamente 30 fps e desenha apenas a página de monitores visível. O Blob do conversor é reutilizado entre arquivos e liberado ao encerrar a página. Os ArrayBuffers PCM são transferidos do Worker para a interface, evitando sua cópia adicional; a entrada original permanece disponível para reconversão. Traduções usam cache limitado e atualizações incrementais de nós.

    Organização

    src separa core, audio, ui, io, i18n, workers, styles e inicialização. scripts contém construção e pacote; docs contém documentação bilíngue; tests contém casos e resultados; assets/soundfonts contém a fonte enviada. A construção usa somente Python padrão e combina os módulos em uma função isolada, sem expor o estado da aplicação globalmente. Os motores reutilizáveis mantêm exportação para testes em Node.

    Validação e limites

    Consulte Validacao.json e tests/results para os resultados por caso. Os testes incluem o parser, PCM, chips, soundfont real enviada, operações da interface, troca de idioma, manutenção de estado, erros, formas de onda e limpeza de áudio. Os VGMs de teste são sintéticos. A interface foi verificada em jsdom com Canvas/Web Audio simulados e Workers de Node. Não houve validação visual/sonora em navegador real nesta revisão; os resultados não garantem ausência de todos os bugs nem precisão musical sobre um catálogo de jogos.

    O suporte a chips não foi ampliado nesta revisão. A transcrição PCM continua monofônica ou por disparos de percussão; misturas e polifonia podem gerar erros. Recursos SF2 avançados continuam parciais e SF3/Ogg não é aceito. MIDI não incorpora samples. Essas limitações e as cotas de recursos estão descritas na ajuda.

    Revision 3.2 · October 15, 2026

    Code review and internationalization

    This revision preserves VGM/GYM conversion and SF2 preview from version 3.1, adds PT-BR/EN selection and organizes source files by responsibility. The final HTML remains self-contained and opens as a local file. The supplied soundfont remains unchanged.

    Languages

    Offline catalogs translate labels, GM options, controls, conversion/error messages, accessibility attributes and diagnostics. Help and review documents are available in both languages. The HTML lang attribute follows the selection. The preference is stored locally with error handling; when storage is denied, language selection still works for the session. No translation service or network request is used. File names, metadata and original SF2 names are preserved.

    Fixes

    The music drop area no longer suggests SF2; imports remain separated by type. Changing PCM page stops its audition to avoid removing a live monitor. Overlapping notes have independent visual lifetimes so a short note ending does not clear a longer held note. Instrument captions follow the selected preview engine. Playback cannot start during conversion or font loading. Diagnostics identify the actual preview engine.

    The sampler cleans up started voices if a later layer fails and respects the remaining playback voice budget. Enable all/disable all controls and a Space shortcut outside input fields are included. Changing language does not rebuild controls or alter settings, queue or playback.

    Optimization

    Oscilloscope input and plotted-trace buffers are reused between frames. Drawing remains limited to approximately 30 fps and the visible monitor page. The conversion Worker Blob is reused across files and released on page exit. PCM ArrayBuffers are transferred from Worker to UI to avoid an additional copy; original input remains available for reconversion. Translation uses a bounded cache and incremental node updates.

    Organization

    src separates core, audio, ui, io, i18n, workers, styles and initialization. scripts contains build/package tools; docs contains bilingual documentation; tests contains cases/results; assets/soundfonts contains the supplied font. The standard-library Python build combines app modules inside an isolated function without exposing application state globally. Reusable engines retain Node exports for testing.

    Validation and limitations

    See Validacao.json and tests/results for individual results. Tests cover the parser, PCM, chips, supplied real SF2, UI operations, language switching, state preservation, errors, waveforms and audio cleanup. VGM fixtures are synthetic. Interface verification uses jsdom with simulated Canvas/Web Audio and Node Workers. No real-browser visual/audio validation was performed in this revision. Results do not guarantee the absence of all bugs or musical accuracy across a game catalog.

    Chip support was not expanded in this revision. PCM transcription remains monophonic or percussion-trigger based; mixtures/polyphony may cause errors. Advanced SF2 features remain partial and SF3/Ogg is unsupported. MIDI does not embed samples. Resource quotas and remaining limits are described in help.

    Research and primary references

    The sources below were checked for document language, optional storage, file filters, transferable buffers, time-domain analysis and SF2/VGM structure. The described optimizations are implementation decisions, not real-device benchmarks.

    • W3C — Declaring language in HTML: html lang and language identification.
    • WHATWG — Web storage: storage access may fail; the preference is optional.
    • WHATWG — File upload: accept is a picker hint; files are also validated.
    • WHATWG — Web Workers: transferable ArrayBuffers reduce copying.
    • W3C — Web Audio API: AnalyserNode, time-domain buffers and currentTime scheduling.
    • E-mu/Creative — SoundFont 2.04: tables, zones, generators, samples and sampler scope.
    • VGM Specification 1.71: header, command and PCM data reference.
