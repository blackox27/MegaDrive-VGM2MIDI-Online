Revision 3.2 · October 15, 2026

Code review and internationalization

This revision preserves VGM/GYM conversion and SF2 preview from version 3.1, adds PT-BR/EN selection and organizes source files by responsibility. The final HTML remains self-contained and opens as a local file. The supplied soundfont remains unchanged.

Languages

Offline catalogs translate labels, GM options, controls, conversion/error messages, accessibility attributes and diagnostics. Help and review documents are available in both languages. The HTML lang attribute follows the selection. The preference is stored locally with error handling; when storage is denied, language selection still works for the session. No translation service or network request is used. File names, metadata and original SF2 names are preserved.

Fixes

The music drop area no longer suggests SF2; imports remain separated by type. Changing PCM page stops its audition to avoid removing a live monitor. Overlapping notes have independent visual lifetimes so a short note ending does not clear a longer held note. Instrument captions follow the selected preview engine. Playback cannot start during conversion or font loading. Diagnostics identify the actual preview engine.

The sampler cleans up started voices if a later layer fails and respects the remaining playback voice budget. Enable all/disable all controls and a Space shortcut outside input fields are included. Changing language does not rebuild controls or alter settings, queue or playback.

Optimization

Oscilloscope input and plotted-trace buffers are reused between frames. Drawing remains limited to approximately 30 fps and the visible monitor page. The conversion Worker Blob is reused across files and released on page exit. PCM ArrayBuffers are transferred from Worker to UI to avoid an additional copy; original input remains available for reconversion. Translation uses a bounded cache and incremental node updates.

Organization

src separates core, audio, ui, io, i18n, workers, styles and initialization. scripts contains build/package tools; docs contains bilingual documentation; tests contains cases/results; assets/soundfonts contains the supplied font. The standard-library Python build combines app modules inside an isolated function without exposing application state globally. Reusable engines retain Node exports for testing.

Validation and limitations

See Validacao.json and tests/results for individual results. Tests cover the parser, PCM, chips, supplied real SF2, UI operations, language switching, state preservation, errors, waveforms and audio cleanup. VGM fixtures are synthetic. Interface verification uses jsdom with simulated Canvas/Web Audio and Node Workers. No real-browser visual/audio validation was performed in this revision. Results do not guarantee the absence of all bugs or musical accuracy across a game catalog.

Chip support was not expanded in this revision. PCM transcription remains monophonic or percussion-trigger based; mixtures/polyphony may cause errors. Advanced SF2 features remain partial and SF3/Ogg is unsupported. MIDI does not embed samples. Resource quotas and remaining limits are described in help.

Research and primary references

The sources below were checked for document language, optional storage, file filters, transferable buffers, time-domain analysis and SF2/VGM structure. The described optimizations are implementation decisions, not real-device benchmarks.

  • W3C — Declaring language in HTML: html lang and language identification.
  • WHATWG — Web storage: storage access may fail; the preference is optional.
  • WHATWG — File upload: accept is a picker hint; files are also validated.
  • WHATWG — Web Workers: transferable ArrayBuffers reduce copying.
  • W3C — Web Audio API: AnalyserNode, time-domain buffers and currentTime scheduling.
  • E-mu/Creative — SoundFont 2.04: tables, zones, generators, samples and sampler scope.
  • VGM Specification 1.71: header, command and PCM data reference.
